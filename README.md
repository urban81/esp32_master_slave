# Реализация нестандартного Master-Slave протокола на ESP32 (ESP-IDF)

Проект реализует кастомный отказоустойчивый протокол обмена данными между двумя платами **ESP32-WROOM** через интерфейс **UART2** на базе операционной системы **FreeRTOS** и фреймворка **ESP-IDF (v5.3+)**.

Особенность прошивки — **универсальность**. Один и тот же бинарный файл зашивается в обе платы, а роль устройства (Master или Slave) определяется аппаратно при старте по уровню напряжения на ножке конфигурации.

---

## 📋 Описание протокола связи

Передача ведется пакетами фиксированной структуры с побайтовым разбором потока через конечный автомат (State Machine).

### Структура кадра (пакета):

| Смещение | Название | Размер | Значение / Описание |
| :--- | :--- | :--- | :--- |
| 0 .. 3 | **Преамбула** | 4 байта | Фиксированный маркер начала: `0x01 0x02 0x03 0x04` |
| 4 | **Длина** | 1 байт | Количество байт в поле данных (N ≤ 255) |
| 5 | **Адрес источника**| 1 байт | `0x01` (Master) или `0x02` (Slave) |
| 6 | **Адрес приёмника**| 1 байт | Адрес назначения пакета |
| 7 .. 7+N | **Данные** | N байт | Полезная нагрузка сообщения |
| 7+N+1 | **CRC (XOR)** | 1 байт | Контрольная сумма всех байт пакета, включая преамбулу |

### Временные ограничения:
* **Таймаут приема пакета:** Максимум **1 секунда**. Если между байтами одного пакета или с момента фиксации преамбулы проходит больше 1 секунды, конечный автомат сбрасывает приемный буфер, защищая систему от зависаний при потере связи.

## 🛠️ Аппаратное подключение (Схема)

Для тестирования обмена соедините две платы ESP32-WROOM по следующей схеме:

```text
    [ ESP32 №1 (MASTER) ]                        [ ESP32 №2 (SLAVE) ]
   .---------------------.                      .---------------------.

   |      GPIO 17 (TX2)  |--------------------->|  GPIO 16 (RX2)      |
   |      GPIO 16 (RX2)  |<---------------------|  GPIO 17 (TX2)      |
   |                GND  |----------------------|  GND                |
   |                     |                      |                     |
   |  3V3 <----> GPIO 4  | (Задание роли)       |  GPIO 4 (В воздухе) |
   '---------------------'                      '---------------------'
```

* **Важно:** Соединение контактов `GND` обязательно для выравнивания потенциалов логических уровней!
* **Выбор роли:** При старте пин `GPIO 4` считывается. Если на нем высокий уровень (`3V3`) — плата становится Мастером и шлет `PING` раз в 2 секунды. Если уровень низкий (встроенная подтяжка к `GND`) — плата становится Слейвом, молчит и отвечает только типа "эхо" (`HELLO MASTER`) на пришедшие пакеты.

---

## ⚠️ Важная настройка памяти (Защита от Bootloop)

На платах ESP32-WROOM пины `GPIO 16` и `GPIO 17` соединены с внутренней Flash/PSRAM памятью модуля. Использование их под UART без настройки вызывает аппаратный сбой ядра (Crash) и циклическую перезагрузку.

**Решение:** В конфигураторе проекта `sdkconfig` (через SDK Configuration Editor) режим работы памяти переключен в **`DOUT`**:
```text
Component config  --->  Serial Flasher Config  --->  Flash SPI mode (DOUT)
```
Это полностью освобождает линии 16 и 17 для стабильной работы пользовательского UART2.

---

## 🚀 Как запустить проект

1. Откройте проект в **Espressif IDE**.
2. Подключите первую плату, замкните на ней `GPIO 4` на `3V3` и нажмите **Flash & Monitor**. Убедитесь, что в консоли пишется `Device role determined as: MASTER`.
3. Подключите вторую плату, оставьте `GPIO 4` свободным, смените COM-порт и залейте эту же прошивку. В консоли должно быть `Device role determined as: SLAVE`.
4. Соедините платы проводами (TX->RX, RX->TX, GND). Начнется автоматический цикличный обмен данными.
